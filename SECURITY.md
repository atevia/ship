# Security Policy

## 🔐 Reporting a Vulnerability

If you discover a security vulnerability in **Ship**, please **do not open a public issue**.

Instead, report it responsibly by contacting:

📧 **security@atevia.studio**

Please include:
- Ship version
- Operating system and architecture
- Detailed steps to reproduce the issue
- Any relevant logs or proof of concept (if available)

We will acknowledge your report as soon as possible and work to resolve the issue promptly.

---

## 🧱 Scope

Security reports may include, but are not limited to:

- Remote code execution
- SSH-related vulnerabilities
- Privilege escalation
- Unsafe file handling
- Command injection
- Insecure defaults
- Authentication or authorization issues

---

## 🚫 Out of Scope

The following are **not considered security vulnerabilities**:

- Misconfiguration of user servers
- Compromised SSH keys
- Weak server passwords
- Issues caused by third-party software
- Lack of system updates on the host machine

---

## ⏱ Response Time

We aim to:
- Acknowledge reports within **72 hours**
- Provide a fix or mitigation as soon as reasonably possible

Please note that response times may vary depending on severity and complexity.

---

## 🤝 Responsible Disclosure

We kindly ask that you:
- Allow reasonable time to address the issue before public disclosure
- Avoid exploiting vulnerabilities beyond proof of concept

---

## 📄 Supported Versions

| Version | Supported |
|--------|-----------|
| 1.x    | ✅ Yes |

Older versions may not receive security updates.

---

Thank you for helping keep **Ship** secure 🙏
